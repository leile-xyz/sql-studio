# MCP 服务与本地 SQL 接口技术方案

配套阅读：[MCP 服务与本地 SQL 接口速览](README.md)；请求链路的上游细节见[架构说明](../architecture.md)。

## 模块划分

| 模块 | 职责 |
|------|------|
| `src-tauri/src/mcp.rs` | axum HTTP 服务：绑定 `127.0.0.1:37625`、`POST /mcp` 与 `POST /sql` 两个路由、Token 校验（`?token=` 或 `Authorization: Bearer`）、JSON-RPC 分发、`McpStatus`（端点、Token、工具清单、错误） |
| `src-tauri/src/mcp_tools.rs` | 6 个工具的定义与实现；`execute_sql` 同时作为 `/sql` 的执行入口 |
| `src-tauri/src/session.rs` | 按 `envId` 解析环境与凭据，产出可直接发请求的会话；跨环境能力的唯一落点 |
| `src-tauri/src/archery/mod.rs` | 登录、CSRF、每环境 Cookie Jar、`/query/` 执行与响应归一化；`is_session_expired` 供上层判断会话失效 |
| `src/lib/mcp-dialog.mjs` + `src/index.html` | MCP 弹窗：状态、两个端点、Token 与重置、工具清单；`?` 打开的接口文档弹窗（`#sqlApiMask`，地址与 curl 示例按当前 Token 渲染） |
| `test/e2e-mcp.js` | 真实应用 + mock Archery 的端到端验证（21 项） |

## 请求链路

```text
MCP 客户端 tools/call execute_sql ─┐
                                   ├─→ mcp_tools::execute_sql(app, arguments)
脚本 POST /sql（JSON 体同款参数） ──┘        │
                                            ├─ 参数校验 / limit 夹紧
                                            ├─ session::ensure_session(app, envId)
                                            │     ├─ 有会话 → 复用
                                            │     └─ 无会话 → 用已保存凭据登录
                                            ├─ ArcheryService::execute_sql
                                            │     └─ POST {origin}/query/（带 CSRF、Origin、Referer）
                                            └─ 会话失效时 relogin 一次并重试
```

界面当前环境不参与该链路：`envId` 是唯一入口，`SessionContext` 按 `(env_id, username, origin)` 分池，因此界面停在线上时调用预发不会互相干扰。

## 会话模型

```rust
struct SessionContext { env_id: String, username: String, origin: String }  // Eq + Hash，作为会话池键
```

- 会话池在 `ArcheryService` 内以 `HashMap<SessionContext, SessionClient>` 保存，进程内共享，切换界面环境不会清除其它环境的会话。
- 解析优先级：复用已有会话 → 用 KV `sqls_creds` 里的用户名 + 凭据管理器中的密码登录 → 返回可操作错误。
- 密码只在 `remember == true` 时从 Windows 凭据管理器读取；接口参数里没有账号密码字段，`mcp_tools` 的单测会断言工具 schema 不含 `username` / `password`。
- 会话被 Archery 判定失效时（响应是登录页 HTML），`parse_response` 返回固定提示，`is_session_expired` 据此触发 `session::relogin` 后重试一次；重试仍失败则把真实错误交给调用方。

## 接口约定

| 项 | 约定 | 理由 |
|----|------|------|
| 端口与 Token | 复用 MCP 的 `37625` 与同一个 Token | 一个客户端配置、一处重置即可覆盖两种调用方式 |
| 鉴权 | `?token=` 或 `Authorization: Bearer` | MCP 客户端沿用了查询参数写法；脚本用头更自然 |
| 请求体 | 与 `execute_sql` 参数一致（camelCase） | MCP 与 HTTP 共用同一实现，避免两套参数模型 |
| 语句数量 | 一次一条 | Archery `/query/` 一次只处理一条；多语句由调用方拆开 |
| `limit` | 默认 100（`DEFAULT_QUERY_LIMIT`），上限 1000 | 防止调用方一次拉走过多数据，超限夹紧并在 `rowLimit` 回显 |
| 失败响应 | HTTP 200 + `{ok:false,error}` | 与 MCP 侧一致：业务失败不是传输失败；401 / 400 只留给鉴权与请求体格式 |
| 写操作 | 不拦截 | 由 Archery 服务端的实例权限与审核兜底，SQL Studio 不做语句判定 |

## 注意事项

- **端口占用**：`37625` 绑定失败时应用照常启动，MCP 弹窗会显示「启动失败」与原因；修复后需重启应用。
- **会话池不落盘**：重启应用后需要重新登录（勾了「记住密码」的环境会自动登录）。
- **并发首次调用**：同一环境并发首次请求会各自登录一次，结果幂等，但会多一次登录往返；如需去重可参考前端的 `recoveryPromises` 思路。
- **端口与 Token 变更**：`reset_token` 立即失效旧 Token，所有客户端需同步更新。
- **改动工具或路由时**：同步更新 `test/project.mjs` 的结构断言、`test/e2e-mcp.js` 的用例，以及本目录两份文档（工具表、契约表）。
- **不要给接口增加账号密码参数**：现有约定是「凭据只来自本地存储」，破坏它会同时影响 README、AGENTS.md 与安全策略的表述。
